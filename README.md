# emacs-configs

Three Emacs profiles on one priced base. Nothing gets in without a number.

| profile | for | state |
|---|---|---|
| `hebrew` | Hebrew org: writing, reading, one export path | stage 1 base only |
| `notes` | English writing and reading | stage 1 base only |
| `ide` | code, LSP, git, projects | stage 1 base only |

Clone and run. No Nix, no OS-specific paths, same checkout on Linux and Windows.

## Run

```sh
bin/emacs-hebrew            # Linux / macOS
bin\emacs-hebrew.cmd        # Windows
```

Each launcher is `emacs --init-directory=<repo>/configs/<profile>`. The base is
shared, so all three read `base/` and differ only in their own `modules/`.

## Layout

```
base/            shared by every profile; may not mention Hebrew, Typst or LSP
  MANIFEST       load order, declared — never inferred from filenames
  early-init.org before the frame exists
  packages.org   package activation, skipped while elpa/ is empty
  core.org       settings: GC restore, VC, processes, encoding, bidi, defaults
  files.org      lockfiles, backups, auto-save
  loader.org     how a profile is assembled (one copy, not three)
  bench.org      measurement, loaded only when MY_BENCH is set
  *.org          the source of truth (literate)
  *.el           generated by bin/build.sh and committed, so a clone runs
configs/<name>/  ten-line bootstrap + modules/*.org + modules/MANIFEST
bin/             build.sh, build.cmd, bench.sh, check.sh, launchers
test/            invariants.el — asserts the agreed settings are in effect
elpa/            one package directory for all profiles (git-ignored)
state/<name>/    history, custom.el, auto-saves (git-ignored)
```

## Build and measure

```sh
bin/build.sh          # tangle every .org, byte-compile, report warnings
bin/build.sh --check  # fail if any .el is older than its .org
bin/bench.sh          # price: floor, per-phase, per-module
bin/check.sh          # prove the agreed settings are actually in effect
bin/gui-test.sh NAME  # GUI launch on a private Xvfb display, off-screen (Linux)
```

## Rules of the house

1. The `.org` file is the source. `.el` files are generated and committed only
   so that `git clone` works with no build step; `--check` fails when stale.
2. Load order is a `MANIFEST`, not a filename prefix. Deciding behaviour by
   which digit a file starts with is what made the previous configuration
   unmaintainable.
3. Nothing enters without a measured price. `bin/bench.sh` is the court.
4. `base/` is profile-agnostic. If only one profile needs it, it goes there.
5. Cheap things may be deferred to an idle timer; deferred things are still
   priced and recorded. An idle timer alone is not trusted: it is postponed by
   frame and focus events, so `my/schedule-idle-modes` pairs it with a
   wall-clock fallback.

## Measured, stage 1 (Emacs 31.1, Linux/NixOS, 2026-11-12)

Numbers move with the file cache, so treat the *delta* as the fact and the
absolute values as fingerprints of this machine.

| what | cost |
|---|---|
| floor: `emacs -Q --batch`, incl. process start (best of 3) | 150–570 ms, cache-dependent |
| Emacs's own startup, up to our `early-init` | 8–15 ms |
| our `early-init` | 4–13 ms |
| base modules (`packages`, `core`, `files`, `loader`) | 2–3 ms |
| **our whole startup cost** | **10–17 ms** |
| idle modes (so-long + delete-selection + which-key, cold) | 11–21 ms, paid 1 s after startup |
| `emacs-init-time`, real tty launch | 0.043–0.060 s |
| `emacs-init-time`, GUI launch (Wayland/PGTK) | 0.72–0.78 s — but `emacs -Q` alone is 0.80–0.96 s, so this is Emacs's own GUI and font startup, not this repository |
| daemon (`--daemon`) to modes-live | < 1.2 s; `emacsclient` round trip ~45 ms |

Deliberately not in: `inhibit-compacting-font-caches` (spends memory
permanently), `bidi-display-reordering` nil (debugging-only, measured no gain),
`most-positive-fixnum` GC (maintainer-warned; 32 MB is as fast), completion
packages, savehist/recentf — all deferred pending decisions.

## Not yet verified (in the repo on purpose, so it is not mistaken for done)

- **No run on Windows or macOS yet.** Relative paths, the `.cmd` twins, the
  desktop trash and the absence of Nix are reasoned, not observed. The first
  `bin\emacs-hebrew.cmd` on Windows is the real test.
- **GUI tests run off-screen.** `bin/gui-test.sh` starts a private Xvfb
  display, because a GUI launch on the user's real display puts windows on
  their screen. Not available on macOS/Windows.
- **No font decision.** The base sets none; the frame picks up whatever the
  system offers (here JetBrainsMono from fontconfig). Hebrew fonts belong to
  the Hebrew profile.
- **`save-interprogram-paste-before-kill`: measured on real Wayland.** With a
  frame open, `(kill-new "KILLED")` while `wl-copy` held `OUTSIDE-TEXT` left the
  kill ring as `("KILLED" "OUTSIDE-TEXT")`, at a cost of **1.5 ms per kill**
  (`gui-selection-value` is the interprogram paste function). It stays on.
  Two caveats worth knowing: in a **frame-less daemon the selection API is
  inert** (reading returned nil and `gui-set-selection` did not take effect
  until a client frame existed), and on X11 the read can block on a wedged
  selection owner — a hazard that does not exist on Wayland, where the
  compositor serves the clipboard.
- **`my/maybe-lighten-large-buffer` is currently dead code**: it hangs off
  `find-file-hook`, but nothing enables line numbers yet. It becomes real in
  stage 4, or it gets deleted.
- **The auto-save redirect also matches remote (TRAMP) files** and has not been
  exercised over a remote connection.
- **`which-key` is a guard, not a dependency**: on Emacs 29 the line does
  nothing. We run 31, where it is built in.

`package.el` activation costs ~200 ms and is therefore conditional: it is
skipped entirely while `elpa/` is empty (see `base/packages.org`).
