#+TITLE: reading — cosmetics off in the hebrew profile
#+PROPERTY: header-args:emacs-lisp :tangle ./reading.el
#+PROPERTY: header-args+: :results none

* Why

This profile exists to read and write large Hebrew org documents. Measured on a
400 KB sefer (230 K characters, 230 footnotes, no headings), the numbers that
decided this file:

| operation                          | cost        |
|------------------------------------+-------------|
| read the file into a buffer        | 4.3 ms      |
| enter org-mode (fonts off)         | 36 ms       |
| fontify one screen                 | 5–7 ms      |
| fontify the whole buffer           | 3,473 ms    |
| the same buffer, footnote face off | 106 ms      |
| the same text with headings added  | 156 ms      |
| scroll one screen (real frame)     | 16–19 ms    |
| scroll one screen, fonts on        | 16.2 ms     |

Two facts follow. Font-lock buys nothing in scrolling — the frame cost is the
same on or off — so turning it off costs only colour. And the whole-buffer
number is not font-lock being slow in general: it is org asking, for every
footnote, which heading encloses it, by scanning backwards to the previous one.
In a transcribed sefer with no headings that scan reaches the top of the file,
230 times.

The verification that the two are the same thing: strip the footnote face and
the whole buffer drops from 3,473 ms to 106 ms; add a heading every fifty lines
to the same text and it drops to 156 ms.

* Priced

0 ms at startup: one minor mode turned off, one hook function defined. The
hook does one regexp search per org buffer, on a list of ~30 entries.

* What is given up, exactly

Colour and nothing else. Folding, headings, tables, links, TODO states, search
and export all work. Footnotes keep being recognised, still jump with =C-c C-c=,
and the exporter still finds all of them — verified on the same file: 115
references parsed with the face removed.

#+begin_src emacs-lisp
;; -*- lexical-binding: t; -*-

;; Colour off, everywhere in this profile. Not a size threshold: a threshold
;; would make the same file look different depending on where it was opened
;; from, and the saving never depends on the threshold anyway — font-lock is
;; the same price per screen at any size.
(global-font-lock-mode -1)

(defun my/org-drop-footnote-highlighting ()
  "Remove org's footnote font-lock keyword from the current buffer.
Font-lock being off already avoids it; this is for a buffer where it was
turned back on by hand, where the cost is seconds rather than milliseconds."
  (setq-local org-font-lock-keywords
              (seq-remove (lambda (kw)
                            (string-match-p "org-activate-footnote-links"
                                            (format "%S" kw)))
                          org-font-lock-keywords)))

(add-hook 'org-mode-hook #'my/org-drop-footnote-highlighting)

;; Org loads its own modules on the first org buffer: 2,109 ms measured, and the
;; first file opened through the daemon pays it. Loading org on a short timer
;; moves that work into the background, where it overlaps with the second or so
;; a person spends choosing a file, instead of sitting in front of the buffer.
;; A plain timer, not an idle timer: an idle timer stops when Emacs is busy, and
;; a daemon with no clients is not always reported as idle.
;; Entering org once is what loads the chain: `require'ing org.el alone leaves
;; `org-load-modules-maybe' to run on the first real sefer, which is the cost we
;; were trying to move. Measured: `(featurep \='org)' was already t and the
;; first open still took 2.5 s.
(run-with-timer
 0.2 nil
 (lambda ()
   (ignore-errors (with-temp-buffer (delay-mode-hooks (org-mode))))))
#+end_src
