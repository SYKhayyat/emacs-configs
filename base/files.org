#+TITLE: files — what Emacs writes next to your work
#+PROPERTY: header-args:emacs-lisp :tangle ./files.el
#+PROPERTY: header-args+: :results none

* Priced

No measurable startup cost, and the run-time cost is on the disk, not the
editor: one write every 30 idle seconds or 300 keystrokes.

Measured on the largest file in the Hebrew corpus (574 KB): one auto-save is
~574 KB, so a full day of typing is under 1 MB per minute — against an SSD
endurance of ~300 TBW, that is centuries. It does not slow Emacs down: the
write happens in idle time and takes 1–3 ms.

* A5 — three different things that are easy to conflate

** Lockfiles** are a symlink created when you first modify a buffer and
deleted when you save. Turning them off removes a file-system operation on
every file you touch and removes the thing that misbehaves on Windows network
drives. What it costs is detection of two Emacs sessions editing one file.

**Backup files** are a full copy written on every save. Off. Version control
is the record of what a file used to be; =.org~= files next to real work are
clutter that no one reads.

**Auto-save** is the one that must stay on. The previous configuration
disabled it, and its own plan file records that a crash therefore loses every
unsaved buffer. It is redirected here instead, so it never leaves litter next
to the file.

#+begin_src emacs-lisp
;; -*- lexical-binding: t; -*-
(defvar my/state-dir)     ; bound in early-init.org

(setq create-lockfiles nil          ; no .#file symlinks
      make-backup-files nil         ; git is the history
      auto-save-default t           ; a crash must not cost unsaved work
      auto-save-file-name-transforms
      `((".*" ,(expand-file-name "auto-save/" my/state-dir) t)))

(make-directory (expand-file-name "auto-save/" my/state-dir) t)
#+end_src
