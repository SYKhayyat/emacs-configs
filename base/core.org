* Priced

Setting variables and two hooks. No package is loaded here, so the cost is
below the resolution of =bench.sh=: this file is a few hundred microseconds of
=eval=, not a load.

* Restoring what =early-init= borrowed

Both thresholds and the handler list are given back exactly once, when init is
over. Restoring from a hook rather than from the last init file means it
happens even if a later module errors.

#+begin_src emacs-lisp
;; -*- lexical-binding: t; -*-
(defvar my/state-dir)     ; bound in early-init.org

(defun my/restore-after-init ()
  "Undo the temporary damage `early-init.org' does on purpose."
  (setq gc-cons-threshold (* 16 1024 1024)   ; 16 MB for a long session
        gc-cons-percentage 0.1)
  (when (boundp 'my/file-name-handler-alist)
    ;; Merge rather than overwrite: handlers registered while init ran (for
    ;; example TRAMP's archive handler) must survive, and the saved list must
    ;; come back. `delete-dups' on pairs compares with `equal'.
    (setq file-name-handler-alist
          (delete-dups (append file-name-handler-alist
                               my/file-name-handler-alist)))
    (makunbound 'my/file-name-handler-alist)))

(add-hook 'emacs-startup-hook #'my/restore-after-init)
#+end_src

* A7 — process output

The default 65,536 is fine for a shell command but is the wrong shape for a
language server, which can emit hundreds of kilobytes in one message. 1 MB is
the largest legal value on Linux: =/proc/sys/fs/pipe-max-size= here is exactly
1,048,576. On Windows and macOS the variable is only a read-chunk ceiling.

#+begin_src emacs-lisp
(setq read-process-output-max (* 1024 1024))   ; 1 MB
#+end_src

* A8 — encoding

UTF-8 for files, processes and the terminal. This is what makes the same files
readable on Linux and on Windows, where the default is otherwise a code page.

#+begin_src emacs-lisp
(set-language-environment "UTF-8")
(prefer-coding-system 'utf-8)
(setq-default buffer-file-coding-system 'utf-8-unix
              default-process-coding-system '(utf-8-unix . utf-8-unix))
#+end_src

* A9 — custom-file

=M-x customize= must never write into a tracked source file. It writes to the
profile's state directory, and anything worth keeping is promoted by hand into
the relevant =.org=.

#+begin_src emacs-lisp
(setq custom-file (expand-file-name "custom.el" my/state-dir))

;; `noerror' covers a missing file, not a malformed one. Measured: two lines of
;; garbage in custom.el made Emacs die before the first frame, and that file is
;; written by Emacs itself, so a crash can leave it corrupt. Refusing to start
;; over a settings file is the wrong trade: report it and carry on, leaving the
;; file in place for inspection.
(condition-case err
    (load custom-file 'noerror 'nomessage)
  (error (message "custom-file ignored (%s): %s"
                  (error-message-string err) custom-file)))
#+end_src

* A11 — text direction

nil is Emacs's own default: each paragraph is laid out from its first strong
character. A Hebrew paragraph goes right, an English paragraph inside the same
sefer goes left, and neither profile has to know which language it is in. This
is a =setq-default=, and no profile overrides it.

Forcing a direction is the old config's most damaging bug, and the price is not
symbolic. Measured on a real frame on this machine, with wrapping on (C15), the
same 43-line screen scrolled a line at a time, min of three runs:

| file                | auto     | forced with the text | forced against it |
|---------------------+----------+----------------------+-------------------|
| 407 KB Hebrew sefer | 4.5 ms   | 4.2 ms (=right-to-left=) | **43.4 ms** (=left-to-right=) |
| 400 KB English      | 5.1 ms   | 3.7 ms (=left-to-right=) | **63.4 ms** (=right-to-left=) |

A keystroke is worse: 3.3 ms auto, 17.1 ms against on the sefer; 4.2 ms auto,
**89.6 ms** against on the English file. The cost is the disagreement, not the
forcing: forced =right-to-left= over Hebrew is free, and forcing either value
over truncated text is free too (4.0–4.5 ms for all three on the sefer). It is
the combination of a forced direction and wrapping that resolves every
displayed line of the paragraph against a base direction the text contradicts.
Measured controls: =bidi-inhibit-bpa= changes nothing (44.1 ms), font-lock off
changes nothing (44.9 ms). Alternating the variable in one session reproduces
and reverts the cost every time (43.4 / 4.0 / 4.2 / 4.1 ms).

Reproduced on two files that are not the one above, five rounds each with the
three directions rotating order every round (so no condition is always the cold
or the hot one), medians: a 340 KB sefer with 358 footnote definitions, forced
=left-to-right= costs **286 ms** a line against 8.1 ms auto — 35× — and 96 ms
against 8.0 ms a keystroke; a 400 KB English file, forced =right-to-left= costs
**163 ms** against 3.3 ms — 50× — and 90 ms against 4.5 ms. So "10×" is a
floor, not a constant: the factor grows with the number of direction runs each
displayed line has to resolve, and across these files and the one in the table
it never once failed to appear.

So the rule is: no direction is forced, anywhere. The consequence nil has, and
the one thing that made the old config force =right-to-left=, is an org footnote
definition: its =[fn:label]= starts with Latin letters, so with nil the definition
is a left-to-right paragraph. The Hebrew profile fixes that for the label alone
(=configs/hebrew/modules/display.org=), rather than for the whole buffer.

=bidi-display-reordering= is deliberately untouched: its docstring says
setting it to nil is for debugging and is not supported, and measurement here
showed no gain (0.20 ms vs 0.20 ms per redraw on a 1.6 MB file).

#+begin_src emacs-lisp
(setq-default bidi-paragraph-direction nil)
#+end_src

* A10 — long lines

=global-so-long-mode= is the built-in answer to minified files and long JSON:
it turns slow modes off in a buffer that would stall redisplay. It is started by
`my/start-idle-modes' below, together with which-key: both are protections
against files and keys you have not touched yet, so both can wait a second.

** Removed: the large-file line-number guard

An earlier version disabled `display-line-numbers-mode' above 1 MB. Nothing in
this base enables line numbers, so the hook could never fire — untested code
that looks like policy, which is precisely what this repository is trying not to
be. It returns in stage 4, where the IDE profile turns line numbers on and the
threshold can be measured against a real file.

* B5 — which-key

Built into Emacs 30 and later, so this is a guard, not a dependency: on Emacs
29 the line does nothing and there is nothing to install. It loads on the
first prefix key, so it costs nothing at startup.

#+begin_src emacs-lisp
(defvar my/idle-modes-started nil
  "Non-nil once the deferred modes have been started.")

(defun my/start-idle-modes ()
  "Start the global modes whose only job is to protect against later trouble.

Measured cold on this machine: `global-so-long-mode' 85 ms, `delete-selection-mode'
16 ms, `which-key-mode' 25 ms. None of them is needed before the first key
press or the first minified file, so all three are paid after `emacs-startup',
when the user is reading rather than waiting.

This is idempotent, because it has two callers: the idle timer and its
fallback."
  (unless my/idle-modes-started
    (setq my/idle-modes-started t)
    (global-so-long-mode 1)
    (when (boundp 'delete-selection-mode)
      (delete-selection-mode 1))
    (when (fboundp 'which-key-mode)
      (which-key-mode 1))))

(defun my/schedule-idle-modes ()
  "Start the deferred modes once Emacs goes idle, and once again by the clock.

An idle timer alone is not enough: it is postponed whenever Emacs has anything
to do — a focus event, a metrics request, a message — and in a GUI session it
was observed not to fire at all in 1 run out of 9. A wall-clock timer cannot be
postponed that way. Either one may win; `my/start-idle-modes' runs once."
  (run-with-idle-timer 1.0 nil #'my/start-idle-modes)
  (run-with-timer 3.0 nil #'my/start-idle-modes))

(add-hook 'emacs-startup-hook #'my/schedule-idle-modes)
#+end_src

* C — Emacs defaults that are wrong for modern use

Not a list of preferences: each line is a default that produces a wrong or
annoying result in ordinary use, and each costs nothing at startup. Anything
that would need a package is not here — it is a package decision.

#+begin_src emacs-lisp
(setq sentence-end-double-space nil   ; C1  "word. Word" is a sentence end
      use-short-answers t             ; C3  y/n instead of yes/no
      delete-by-moving-to-trash t     ; C4  delete uses the desktop trash
      use-dialog-box nil              ; C5  no native modal dialogs …
      use-file-dialog nil             ;     … for file selection either
      scroll-conservatively 101       ; C6  scroll a line, don't re-centre
      scroll-preserve-screen-position t ; C7  keep text still under C-v/M-v
      auto-save-no-message t          ; C9  it saves either way; stop narrating
      ring-bell-function #'ignore     ; C10 no bell on a failed command
      enable-recursive-minibuffers t  ; C11 open a file from inside a prompt
      save-interprogram-paste-before-kill t ; C12 don't clobber the clipboard
      vc-follow-symlinks nil)         ; C14 visit the link, don't ask

;; C2 and C8 are automatically buffer-local, so they need `setq-default' to
;; reach buffers that do not exist yet. (One form each: a trailing comment
;; after a multi-line `setq' would swallow the closing paren.)
(setq-default indent-tabs-mode nil)     ; C2  no tabs written into files
(setq-default require-final-newline t)  ; C8  no missing-newline diffs
#+end_src

C13 (`delete-selection-mode', 16 ms to load) is started by
`my/start-idle-modes' above, with the other modes nobody needs in the first
second.

** C15 — no line runs off the edge

Org's startup default truncates long lines at the window edge
(=org-startup-truncated= is t), and this profile set nothing to the contrary:
measured on the 407 KB sefer, =truncate-lines= was t and every paragraph wider
than the frame was displayed cut off at the edge. A line that cannot be
finished is a line that did not render.

=word-wrap= is set as a default because it is automatically buffer-local, so
=setq-default= is what reaches buffers that do not exist yet; =so-long= and
plain text buffers then break at word boundaries instead of splitting a Hebrew
word across two lines. =visual-line-mode= is what turns that into displayed
lines, and at the same price makes =C-a=/=C-e= act on the line the user sees.

Price, on that sefer: 3.8–4.4 ms per line scrolled when wrapped, against
4.2–4.8 ms when truncated. Wrapping is inside noise. The 41–45 ms figure that
made wrapping look expensive belonged to the forced =left-to-right= that A11 no
longer sets, not to wrapping: the same file with the same wrapping and no
forced direction scrolls in 4.2 ms.

This covers every buffer: text-derived modes (org among them, through
=text-mode-hook=) get =visual-line-mode=, and nothing in this repository sets
=truncate-lines= to t.

#+begin_src emacs-lisp
(setq-default word-wrap t)               ; C15 soft breaks land at a word boundary
(add-hook 'text-mode-hook #'visual-line-mode)
#+end_src

**Deliberately not here.** `line-move-visual' stays at Emacs's default (visual
movement): it belongs to the Hebrew profile, where physical line movement is
wrong for wrapped RTL text. `fill-column' stays at 70 and belongs to the
profiles that fill prose. The centred column is =olivetti= — a package, and so a
profile decision (=configs/hebrew/modules/display.org=).
