#+TITLE: packages — activation, and why it is conditional
#+PROPERTY: header-args:emacs-lisp :tangle ./packages.el
#+PROPERTY: header-args+: :results none

* Priced

**The measurement that shaped this file.** Requiring =package.el= and
activating packages costs about *200 ms* on this machine, with an /empty/
package directory: =package.el= pulls in =url=, parts of Gnus, and the rest.

Measured (bin/bench.sh, Emacs 31.1):

| phase | ms since process start |
|-------+------------------------|
| Emacs's own startup, up to our =early-init= | 25–28 |
| + =require package= and activation | 228 |
| + all base modules | 248 |

So this file does nothing at all while there are no packages to activate, and
pays the 200 ms only once the repository actually has some. A configuration
whose first job is to be fast should not spend a quarter of a second
activating an empty directory.

* A second, less obvious reason: determinism

=package-directory-list= is emptied. By default it also points at the
system-wide package directory; on this machine that is 111 packages whose
autoloads are all activated, which both costs time and lets an unknown
environment change the editor's behaviour. One clone, one package directory,
same behaviour on Linux and on Windows.

#+begin_src emacs-lisp
;; -*- lexical-binding: t; -*-
(defvar my/state-dir)     ; bound in early-init.org
(defvar package-archives) ; defined by package.el, which may not be loaded yet

(setq package-directory-list nil)

(defun my/packages-present-p ()
  "Non-nil when the shared package directory holds at least one package."
  (let ((dir (and (boundp 'package-user-dir) package-user-dir)))
    (and (stringp dir)
         (file-directory-p dir)
         (seq-some (lambda (entry)
                     (and (file-directory-p entry)
                          ;; These two live in elpa/ but are not packages.
                          (not (member (file-name-nondirectory entry)
                                       '("archives" "gnupg")))))
                   (directory-files dir t "\\`[[:alnum:]]" t)))))

(when (my/packages-present-p)
  (require 'package)
  (add-to-list 'package-archives '("gnu" . "https://elpa.gnu.org/packages/") t)
  (add-to-list 'package-archives '("melpa" . "https://melpa.org/packages/") t)
  (package-initialize))
#+end_src

* When packages arrive

The 200 ms is a tax on every start. Two ways to spend less, both to be
measured before adoption:

- =package-quickstart= (built in): a generated file that activates packages
  without loading =package.el=. It trades the 200 ms for the discipline of
  refreshing the file whenever the package list changes.
- Install rarely and accept the 200 ms: with a daemon it is paid once per
  boot.

Not decided yet. When the first package lands, both get measured and the
numbers go here.
