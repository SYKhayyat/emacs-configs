#+TITLE: early-init — what runs before the frame exists
#+PROPERTY: header-args:emacs-lisp :tangle ./early-init.el
#+PROPERTY: header-args+: :results none

* Why this file exists

=early-init.el= is read before Emacs creates its first frame. Anything that
changes how the frame is /created/ has to happen here, or the work is already
spent by the time =init.el= runs.

Shared by every profile. It may not mention Hebrew, Typst, LSP or any other
profile-specific idea.

* Priced

No measurable cost: it sets variables and turns three UI modes off. The bare
=emacs -Q --batch= floor on this machine is 720–770 ms; this file adds no load.

* Paths: one repo, three profiles, one package directory

Each profile starts with =emacs --init-directory=<repo>/configs/<profile>=, so
=user-emacs-directory= is the profile directory and =my/repo-root= comes from
the two-line loader in that directory. Packages install once into
=<repo>/elpa= and are shared by all three profiles. Run-time files go to
=<repo>/state/<profile>=, which is git-ignored.

#+begin_src emacs-lisp
;; -*- lexical-binding: t; -*-
(defvar my/profile)      ; bound by the profile loader
(defvar my/repo-root)    ; bound by the profile loader

;; Measurement lives in bench.org and is loaded only for a benchmark run, so a
;; normal start neither defines nor calls any of it.
(declare-function my/mark "bench" (label))

(when (getenv "MY_BENCH")
  (load (expand-file-name "base/bench.el" my/repo-root) nil 'nomessage)
  (my/mark "0 Emacs startup → our early-init"))
(defvar my/state-dir
  (expand-file-name (format "state/%s/" my/profile) my/repo-root)
  "Per-profile directory for files Emacs writes at run time.")

(make-directory my/state-dir t)

(setq package-user-dir (expand-file-name "elpa" my/repo-root)
      ;; Packages are activated by the loader, so activation order is visible
      ;; in `init-base.el' instead of implied by directory listing order.
      package-enable-at-startup nil)
#+end_src

* A1 — garbage collection during startup

The default 800 KB threshold triggers GC repeatedly while init files cons.
32 MB at 20 % is what a controlled experiment found equal to
=most-positive-fixnum=, without the maintainer's warning about it. Restored to
a modest value in =core.org=.

#+begin_src emacs-lisp
(setq gc-cons-threshold (* 32 1024 1024)   ; 32 MB
      gc-cons-percentage 0.2)
#+end_src

* A2 — file-name-handler-alist

Every file operation consults these handlers; init does many file operations.
Nothing local needs them yet, so the list is emptied here and restored from
=emacs-startup-hook= in =core.org=.

#+begin_src emacs-lisp
(defvar my/file-name-handler-alist file-name-handler-alist
  "The real handler list, saved while init runs.")

(setq file-name-handler-alist nil)
#+end_src

* A3 — UI elements, before the frame exists

Turning these off here means the frame is never created with them, so nothing
is built and hidden, and =frame-inhibit-implied-resize= stops font changes
from triggering geometry recalculation mid-init.

#+begin_src emacs-lisp
(menu-bar-mode -1)
(when (fboundp 'tool-bar-mode) (tool-bar-mode -1))
(when (fboundp 'scroll-bar-mode) (scroll-bar-mode -1))

(setq inhibit-startup-screen t
      inhibit-startup-message t
      inhibit-startup-buffer-menu t
      initial-scratch-message nil
      frame-inhibit-implied-resize t)
#+end_src

* Not here

=inhibit-compacting-font-caches= (A4) was considered and left out: it spends
memory permanently to fix a symptom not observed here. One line if it appears.
